## 한 줄 요약

프로젝트 폴더에 **`index.html` + `custom.js`** 가 직접 들어가는 8th Wall 식 구조로 전환 (Phase 1).
**인-앱 Monaco 코드 에디터** ("Code" 탭) 추가로 작가가 외부 IDE 없이 바로 커스텀 코드 편집 (Phase 2a).
런타임 엔진 (`runtime-prototype/runtime/`) 은 에디터 소유 그대로 — Unity 엔진 모델.

---

## 왜 이 방향인가 (소프트웨어 엔지니어링 관점)

### 우리가 거부한 것: Variant B (전체 runtime 도 프로젝트 폴더로)
WordPress 테마 / Create React App 의 ejected 상태와 같은 **upgrade-path 함정**. 한 번 user-owned 가 되면 이후 runtime 버그 fix 가 기존 프로젝트에 자동으로 안 흘러감. 1년 안에 "왜 내 옛 프로젝트는 새 기능 못 써?" 문의 도배 예상.

### 우리가 채택한 것: Variant C (얇은 사용자 후크 레이어)
Unity / Godot / Astro / Vite plugin / WordPress child theme 패턴. **runtime 은 버전 핀된 의존성, 프로젝트는 user content + 명시적 hook 파일.**

```
runtime-prototype/runtime/  ← 에디터 엔진 (Unity 의 binary 위치). 사용자 안 만짐.
project-folder/
  index.html       ← 사용자 + sentinel-managed 영역 혼합
  custom.js        ← 사용자 hook (register(api) export)
  config.json      ← auto-gen (Save 시 갱신, MVP 3 까지의 흐름 그대로)
  *.webar.json     ← 에디터 메타
  assets/          ← 작가 임포트
```

런타임 업데이트 시 sentinel 사이만 갱신, 사용자 코드는 보존. custom.js 가 vibe coding surface.

## Phase 1 — Project-as-Site 토대

### 1-1. Sentinel-managed sections in index.html
형식 (LOCKED): `<!-- editor:managed-<name> START -->` ... `<!-- editor:managed-<name> END -->`. 두 영역:
- `managed-imports` — importmap (MindAR 의 `import 'three'` 해소). 우리가 dep 추가하면 갱신 가능
- `managed-bootstrap` — `import { ARSceneLoader } ... ` 시작 스크립트. 우리가 boot flow 바꾸면 갱신 가능

밖의 영역 (CSS, body markup, start overlay 카피, 에러 배너 디자인) 은 **순수 사용자 영역**. 절대 안 건드림.

구현: `src-tauri/src/commands/template.rs` 의 `replace_managed_section` / `extract_managed_section`. 단순 substring replacement (HTML parser 안 씀 — robust). 4개 단위 테스트 통과.

### 1-2. project_new 동작 변경
새 프로젝트 시점에 `runtime-prototype/index.html` 을 템플릿으로 읽어 `<title>` 만 사용자 입력값으로 substitute, 프로젝트 폴더에 복사. `custom.js` stub (빈 `register(api)` export) 도 같이 생성.

template 이 안 보이는 release bundle 케이스는 graceful skip (warn log, 계속 진행).

### 1-3. 마이그레이션 (이전 프로젝트 호환)
- `project_needs_template_materialization(path) -> bool` — `index.html` 또는 `custom.js` 부재 감지
- `project_materialize_template(path) -> ()` — idempotent. 있는 파일은 안 건드림
- 프론트: `openProject` 가 자동 호출 → 부재 시 `pendingMigrationPath` set → `<MigrationModal>` 등장 → "Add files" / "Not now"

### 1-4. Preview / Export 단순화
`do_export` (preview 도 공유) 가:
- `<project>/index.html` 우선 사용. 없으면 `runtime-prototype/index.html` fallback (warn log)
- `<project>/custom.js` 있으면 export root 에 복사
- `runtime/` 은 여전히 `runtime-prototype/runtime/` 에서 복사 (에디터 소유)

결과적으로 `.preview-tmp / output` = **프로젝트 폴더 + runtime/** 합본. 작가가 `index.html` 편집한 게 즉시 미리보기/export 에 반영.

### 1-5. 런타임의 register(api) hook 시스템
`ar-scene-loader.js` 가 startup 시 `await import('../custom.js')`. import 실패해도 런타임 안 죽음 (try/catch + warn).

API surface (LOCKED v1):
```js
api.onAction(type, handler)        // 새 action type 핸들러. (node, ctx) => void. 빌트인 type 도 오버라이드 가능 (1회 로그)
api.onTargetFound(handler)         // 추가 리스너. (ctx) => void
api.onTargetLost(handler)          // 추가 리스너. (ctx) => void
api.onFrame(handler)               // 매 프레임. (delta, ctx) => void
api.beforeStart(handler)           // mindar.start() 직전 1회. async 허용
```

ctx: `{ getObject(id), playSound(src), scene, camera, anchor }`. 모든 사용자 핸들러는 try/catch 격리 — 한 핸들러가 던져도 런타임은 계속 동작.

custom.js stub 의 example 주석에 `action.shake` 등록 예시 박혀 있음 (작가가 패턴 카피해서 시작).

## Phase 2a — In-app 코드 에디터

### 2a-1. Code 탭 (BottomTabs)
새 탭 `Code` 가 Interaction 옆에 (Interaction / **Code** / Signal Binding / Mobile Log).
React.lazy + Suspense — Monaco 번들 (~5MB) 이 탭 활성화 직전까지 안 로드됨.

### 2a-2. 파일 접근 (`fileApi`)
Tauri 측 `commands/file.rs` 의 `file_read` / `file_write`:
- **Whitelist (LOCKED v1)**: `index.html`, `custom.js` 둘만. 다른 경로는 `Err`
- **경로 검증 (defense in depth)**: `project_dir.canonicalize()` 후 `intended.starts_with(project_canon)` — `..` traversal 차단. 단위 테스트 2개 (whitelist reject, traversal reject)

프론트: `src/tauri/api.ts` 의 `fileApi.read/write` 래퍼.

### 2a-3. CodeTab.tsx 동작
- 좌상단 파일 셀렉터 — `custom.js` / `index.html` 두 개. dirty 시 `•` 마커
- 우상단 액션 버튼 — Save / Reload / Open in Finder
- 메인 영역 — Monaco 에디터 (`@monaco-editor/react`, vs-dark, 자동완성 / 신택스 무료)
- `index.html` 활성화 시 커서가 sentinel 영역 안에 있으면 노란 경고 배너 ("This area is managed by the editor and may be overwritten on runtime updates.")

### 2a-4. UX 디테일
- **Cmd+S** — Code 탭 active + Monaco focus 시 인터셉트해 활성 파일만 저장. 프로젝트 레벨 Save 와 분리
- **Reload** — dirty 면 confirm 후 디스크에서 재읽기 (외부 IDE 로 편집한 경우 동기화)
- **Open in Finder** — `@tauri-apps/plugin-opener` 의 `openPath(projectPath)` — OS 파일 매니저로 폴더 열기

## 파일 소유권 표 (최종)

| 경로 | 소유 | 갱신 시점 |
|---|---|---|
| `runtime-prototype/runtime/*.js` | **에디터** (Unity 엔진 위치) | 에디터 버전 올리면 자동 |
| `<project>/index.html` | 혼합 — sentinel 안 = 에디터, 밖 = 사용자 | sentinel 영역만 (Phase 3 에서 자동 갱신 워크플로우 추가 예정) |
| `<project>/custom.js` | **사용자** | 갱신 안 함. 빈 stub 으로 시작 |
| `<project>/config.json` | 에디터 (auto-gen) | preview/export 시 |
| `<project>/{project,graph,bindings}.webar.json` | 에디터 | Save 시 |
| `<project>/assets/` | 사용자 | 임포트 |

## 알려진 sleeper 이슈 (이번 phase 에서 확인된)

이번 세션은 큰 함정 없이 부드럽게 진행. 다만:

### Vite HMR 의 transient resolve 에러 (서브에이전트 병렬 작업 시)
- 증상: 한 에이전트가 BottomTabs 에 `import "@/editor/code-tab/CodeTab"` 추가 → 다른 에이전트가 아직 CodeTab.tsx 안 만든 시점에 Vite 가 `Failed to resolve import` 에러
- 영향 없음: 두 번째 에이전트가 파일 만들면 자동 회복
- 교훈: 에이전트 병렬 분배 시 의존하는 파일이 먼저 생성되도록 contract 명시 (이번엔 contract 만 LOCK 했고 순서는 안 잠갔음)

### `@tauri-apps/plugin-opener` 의 JS 패키지 추가 필요
- Rust 측 `tauri_plugin_opener::init()` 은 이미 있었지만 JS 측 `@tauri-apps/plugin-opener` 는 별도 npm 패키지 — 처음에 누락됨
- Capabilities 에는 이미 `opener:default` 들어있어 권한 문제는 없었음
- Phase 2a 에서 `npm install @tauri-apps/plugin-opener@^2.5.3` 추가됨

## 검증 흐름

### A. 새 프로젝트
1. New Project → 빈 폴더 선택 + 이름 입력
2. Finder 로 그 폴더 확인 → `index.html` + `custom.js` + JSON 3종 + `assets/` 모두 보임
3. `index.html` 외부 에디터로 열어서 sentinel 마커 확인 가능

### B. 기존 프로젝트 마이그레이션
1. Open Project → 이전 세션 프로젝트 선택
2. **"Update project files" 모달** 자동 등장
3. "Add files" 클릭 → idempotent materialize → 이전 그래프/에셋 그대로 보존

### C. Code 탭 (Phase 2a)
1. Bottom Tabs → Code 탭 클릭 → Monaco 로딩 (~1초) → custom.js 활성화
2. 한 줄 추가 → dirty `•` → Save 버튼 → 디스크 mtime 갱신
3. index.html 탭 → 커서를 `<!-- editor:managed-imports START -->` 영역 안으로 → 노란 배너 등장
4. **Open in Finder** → 프로젝트 폴더 열림

### D. Vibe coding end-to-end
1. CodeTab 의 custom.js 에 `api.onTargetFound((ctx) => console.log('hi'))` 추가 → Save
2. Preview 재시작 (자동 watcher 는 아직 없음 — Phase 2b)
3. 카드 인식 → 콘솔 `[custom.js] register(api) 호출 완료` + `hi`

## 다음 단계

### Phase 2b — 운영 디테일
- **자동 reload** — 파일 변경 시 preview 자동 재시작 (FS watcher). 현재는 사용자가 수동 재시작

- Claude API key 사용자 등록 (Settings)
- 자연어 프롬프트 → diff preview → accept/reject UX
- AI 컨텍스트로 register(api) docstring + 현재 scene 상태 자동 주입

### Phase 4 — 다른 기능 흐름
- (별도) MVP 4 Signal Binding — Data 노드 활성화 + 매 프레임 바인딩 런타임

- (별도) WebXR hit-test 보강 — Android Chrome 한정 spatial 옵션
